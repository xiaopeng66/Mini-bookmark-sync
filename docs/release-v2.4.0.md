# v2.4.0 发布说明

本版是 2.3.0 之后的累计版本：修好跨设备移动书签的位置同步，并让手机端在浏览器不支持移动时也不丢书签。

## 相对 2.3.0 的主要变化

### 移动书签 / 文件夹

- 在一端把书签或文件夹移到另一个文件夹，同步后另一端能拿到新位置，不再被还原到原处；源文件夹里只有这一项时同样传播。
- 移动方向以「上次同步时这个书签在哪里」为准，本机残留的旧移动记录不会再反向覆盖云端。
- 同步进行中拖动书签也会被记录，不再因为「正在同步」而丢失这次移动。
- 剪切/粘贴式移动（新建副本再删掉原书签、编号会变）、网址只差末尾斜杠、移动同时改标题，都能识别为同一次移动。
- 手机端移动书签时按多种调用形式依次重试（带 index、数值型父节点编号、`browser.*` Promise 版、无回调 Promise 版），宿主支持任意一种即可自动生效。
- 移动确实无法落地时明确报错并原样保留两端书签，不再自动「新建一份再删掉旧的」；此前版本因此少掉的书签，云端仍保留，下一次合并会自动导回。
- 写回云端前会复核移动是否真的落地，有一处不对就停止写回，云端保持原样。

### 自动同步

- 浏览器打开、配置检查通过后自动额外同步一次，不必等定时间隔到点；与「错过补跑」不会重复执行。

### 本地恢复与提示

- 设置页新增「本地书签恢复」：查看未完成的事务备份、导出当前书签与备份、确认后再恢复。
- 检查后确认无需补回任何书签时按成功处理，不再显示失败；已确认完成的同步只补记状态，不用旧备份覆盖当前书签。
- 同步进行中不再误报「有未完成的本地事务」；只有同步结束、事务确实没收尾时才提示。
- 「本服务未提供可用的并发校验」这类能力提示同一级别只提示一次，不再每轮同步重复。

### 数据安全

- 上传 / 合并提交后的基线改记「实际写进云端的树」，同步等待期间的新移动不会被误判成「跟随云端」而迁回原位。
- 上传、下载、合并三条路径共用同一份删除记录与恢复口径；失败回滚只撤销本事务新建的节点。

## 验证与限制

- **936/936 JavaScript 测试通过，51 个测试文件**。
- **6/6 打包工具测试通过**；生产 JavaScript 语法与差异空白检查通过。
- 验证运行真实生产模块，Chrome API、存储与网络为隔离模拟；本次没有操作真实书签或生产 WebDAV。
- **没有完成真实手机、浏览器 GUI、生产 WebDAV 厂商兼容性验证**，不承诺不存在其他缺陷。
